# PeakCast — Weather Chatbot for Alpine Sports in Austria

**Course:** Project: AI Use Case (IU International University, MSc Artificial Intelligence)
**Author:** Markus Pointner (IU14161364)
**Phase:** 2 — Implementation

---

## 1. Project goal

PeakCast is a chatbot that answers short weather forecast questions for people doing
outdoor and alpine sports in Austria — hikers, climbers, ski tourers and paragliders.

A user asks in plain English, for example *"How windy is it on the Hochkönig tomorrow?"*,
and gets a **one or two sentence answer with exact values, units and a short outdoor hint**.

The bot covers:

| Topic | Status | Why it matters |
| --- | --- | --- |
| Temperature | mandatory | layering, hypothermia risk |
| Sky condition (sunny / cloudy) | mandatory | summit view, orientation |
| Wind speed and gusts | mandatory | decides whether a paraglider can launch |
| Rain and snowfall | optional | fresh snow matters for ski tours |

PeakCast informs — it does **not** replace official mountain weather or avalanche reports.

## 2. Technical approach

Everything is plain Python so that every component stays transparent and no cloud
account or license key is needed. Deliberately **not** used: hosted chatbot frameworks
(Rasa, Dialogflow) and LLM APIs.

```
Streamlit chat UI
      ↓
Dialogue manager          (keeps last place, limits conversation length)
      ↓
NLU   ├─ intent classifier   (scikit-learn: TF-IDF + logistic regression)
      └─ slot extraction     (place from GeoNames Austria, day words by rules)
      ↓
Weather service           (Open-Meteo API, offline JSON dataset as fallback)
      ↓
Response generator        (templates with values, units and outdoor hint)
```

## 4. Setup

Requires **Python 3.12** (3.10–3.12 all work).

Check which versions are installed with `py --list` on Windows or
`python3 --version` on Linux/macOS. On Windows, avoid the bare `python` command:
if Python was never installed from the Microsoft Store it resolves to a stub that
reports no version at all. The `py` launcher is reliable.

### Windows (PowerShell)

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Linux / macOS

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

All dependencies are pinned to exact versions in `requirements.txt`, so the
environment can be rebuilt identically.

### Running the intent classifier

Run in this order from the project root:

```bash
python scripts/train_intent.py                     # baseline: 5-fold CV, saves the model
python scripts/evaluate_intent.py                  # baseline test metrics -> reports/
python scripts/optimize_intent.py                  # iteration 1: grid search + threshold
python scripts/evaluate_intent.py --variant iter1  # iteration 1 test metrics -> reports/
python scripts/compare_iterations.py               # before/after chart + spot-checks
python scripts/try_intent.py                       # interactive: type a sentence
```

| Model | CV accuracy (train) | Test accuracy | Macro F1 |
| --- | --- | --- | --- |
| Baseline — word TF-IDF + logistic regression | 0.678 | 0.775 | 0.778 |
| **Iteration 1** — word + character n-grams, grid-searched | **0.803** | **0.813** | **0.812** |

All metrics, confusion matrices, the grid search table and every misclassified
sentence are written to `reports/`.

### Running the slot extraction (step 5)

```bash
python scripts/build_places.py        # download GeoNames, write data/places_at.csv
python scripts/evaluate_slots.py      # slot metrics -> reports/
python -m pytest                      # 112 unit tests
```

`scripts/build_places.py` only needs to be run to rebuild or refresh the place
list - `data/places_at.csv` is committed, so the bot works straight from the
submitted files.

| Slot | Accuracy on `data/slots_test.csv` (52 sentences) |
| --- | --- |
| Place | **0.981** (51/52) |
| Day | **1.000** (52/52) |
| Part of day | **1.000** |

Measured against a fixed reference date (Wednesday 2026-11-04) so that relative
day words like *"on Friday"* stay reproducible. See `reports/metrics_slots.json`
and `reports/slot_extraction_check.csv`.

> **Safety note:** the intent classifier labels *"avalanche risk after the fresh
> snow"* as a precipitation question with high confidence (p = 0.62, well above
> the 0.35 fallback threshold), and the better model is the more confidently
> wrong one. Avalanche questions are therefore intercepted by a rule-based guard
> in `peakcast/safety_guard.py` that runs **before** the classifier and returns a
> fixed referral to the official avalanche warning service, never a forecast.
> See `DEVLOG.md`, steps 2, 4 and 5.
